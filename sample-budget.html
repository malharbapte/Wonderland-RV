Budget field — five ways in

The contact form, at real desktop scale, with a Budget question added five different ways. Everything else in the form is untouched. Desktop only — the new field is hidden below 900px in every option, so nothing here can reach the phone layout before we work on it deliberately.

Two things to settle, whichever you pick
  • The numbers are placeholders. I used Under $100k / $100–140k / $140–180k / $180k+ / Not sure yet. I have no price list from you and none is published on the site, so confirm or replace these bands before we ship.
  • Optional, not required. No red asterisk in any option, and every one includes a "not sure yet" escape. Budget is the question people abandon a form over; forcing it costs enquiries. Say the word if you want it required.

Option 1 — the straightforward oneOne more of the same

no new components+109

A fourth row on the existing grid, with Budget as a second rounded select directly under State — same width, same height, same radius, same chevron. The new row repeats row 3's height exactly, so the 40px of air above State is the 40px above Budget. Nothing new is invented: if you only want the field to exist and behave, this is it. The cost is an empty right-hand cell and a full extra row of height for one question.

Option 2Full width, above the pill

on-language+109

Budget leaves the two-up grid and takes the textarea's width instead (11.4737rem). That reads as a deliberate single question rather than half a row, and it joins the form's lower half — pill, notes, consent — which are all full-width already. It costs exactly the same height as Option 1 — 109 artboard px either way, because a 40 gap plus a 69 select is the same as repeating row 3 — so the choice between them is purely about where the question belongs, not about space. No empty cell, though. The one thing to look at is whether a 1,148px-wide dropdown holding "$140,000 – $180,000" feels generous or feels empty.

Option 3A second pill, deliberately quieter

strongest brand echo+95 — shortestdilutes the signature element

The travelling orange thumb is this form's signature, so the most Wonderland answer is to use it again. To stop the two pills competing, this one is subordinate on purpose: 70px tall against the main pill's 110, type at 0.24rem against 0.32, a tighter radius. Same easing, same squash as it travels.

Something this option forced into the open. A segmented pill has no way to show "unanswered" — the thumb has to sit somewhere, so whatever cell it starts in is a silent answer on every form that gets submitted untouched. My first pass defaulted to "Under $100k", which is the worst possible silent answer to give your sales team. So this pill has five cells, opening on "Not sure yet". Options 1, 2, 4 and 5 can all genuinely start empty; this one cannot.

Flagging this one too. Two pills stacked starts to read as a survey rather than a form, and the main pill loses some of its status as the one place you choose something. It also doubles a piece of known debt — the thumb script is already copied in home.js and video.js and the two copies have drifted. If you like this, the pill logic should come out into one shared file first.

Option 4 — your pick, revisedA stepped track

brand vocabulary+160new interaction

The amounts now sit on the nodes. Each node is placed at its value along the track rather than in an equal flex cell, and the amount hangs directly beneath it. The track measures 453–1071 on screen, the same left and right edges as the textarea below it; the outer two nodes are inset by half a dot so they stay inside the track instead of poking past the form's left margin, and the outer two labels align to the ends so they cannot run past the measure. The orange fill ends exactly on the chosen node, computed from the same expression that places the node, so the two can never drift apart.

The under-$100k band is marked, not just explained. Pick it and a cream note opens underneath — "Sorry, we don't have any vans under $100,000." More than that, this node never turns brand orange. It fills grey, its label stays grey, and the track stays empty, because a colour that means "chosen, good" everywhere else on the site would contradict the sentence sitting under it. The note opens on the accordion's own easing rather than holding 23px of empty space on every form nobody ever sees it on.

"Not sure yet" had to come off the track. Once the amounts sit on the nodes, the track is a real monetary scale, and a node at the far right means the most — it cannot also mean I don't know. It now rides the label row opposite BUDGET, in the same radio group so it stays mutually exclusive, and it costs no extra height. Choosing it empties the track.

Nothing is selected when the form loads: empty track, an em dash where the amount goes. The field costs 160 artboard px.

Two things left for you. The copy is your sentence verbatim — say if you want a second clause pointing people at where the range does start. And the four bands are still placeholders until you confirm them; that matters more now, because the track publishes them as a scale rather than hiding them in a dropdown.

Option 5 — the one that breaks the rulesCharcoal tiles

off-language on purpose+206 — tallest

This is the outlier you asked for, and it is not Wonderland — no orange anywhere, a 3px radius against the site's 14.6, letter-spaced micro-caps at 11px, tabular numerals, and a solid charcoal fill on the chosen tile. It behaves like a pricing table from a software product. It's included so you can see where the boundary actually is: it's clean, it's fast to read, and it's obviously from a different house. My read is that it would look imported, but you make that call.
